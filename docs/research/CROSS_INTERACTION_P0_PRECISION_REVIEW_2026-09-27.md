# P0 测量精度复核方案

日期：2026-09-27。状态：**方案完成，未实现、未运行，不是运行声明。** 当前只解决效用能否可信地测量，不进入 P1 或开发门控。

## 1. 已知事实与需要纠正的解释

来源为 [P0结果审计](CROSS_INTERACTION_P0_AUDIT.md)、启动提交 `aca59c5cfba5df5768eb68a3b02c226e084cb41f` 的 `codes/cross_interaction_p0.py` 及原 `report.json`（SHA256 `9eee8804963aa2db9691d53472d94350b8dafeb95d56000e68e80219d9fac02a`）。只读核对发现：

1. `per_loss` 用 float32 embedding 做点积、margin 和 logsigmoid；`la.double()-lb.double()` 发生在损失已算完之后。提升减法精度不能恢复之前舍入掉的信息。
2. 旧 `resolution_bound=8*eps32*max(1,abs(lossA),abs(lossB))` 在36项报告中全为 `9.5367431640625e-7`；最大 `abs(U1)=7.460506878942397e-9`，相差约127.83倍。这个阈值不是传播完整点积/非线性误差得到的严格上界，也没有经过实测校准；有些情况下可能过松，有些情况下也不能保证覆盖误差。
3. 零干预逐位一致说明相同路径可重复，不代表非零干预的差分准确。六项干预的参数差范数非零，说明实际float32更新产生了可表示差异；范数非零不能保证探测效用可识别。
4. 旧产物保存了损失差、均值、方差、参数差范数，没有保存更新后参数行、原始margin或两侧loss。因此仅靠JSON无法恢复高精度效用，也不能从现有差值反推出真实舍入误差。

**解释收窄：旧结果仍是“未通过预声明的保守分辨率筛查”。不能更强地断言真实效用低于已测数值噪声，不能认定全是float32伪差异，也不能在看过结果后直接降低旧阈值，把旧运行改成通过。** 原审计、原resolved=false与原声明均保留。

## 2. 保持不变的干预对象

目标仍是同一个原始float32模型/AdamW状态、同一BPR batch下的两个**实际float32更新后状态** A/B，对同一探测分布的BPR surrogate差。保留原warm checkpoint、moment、step60562、lr/decay、KD系数、multiplicity和batch×64归约。新探测计算只读这些更新后的数值。

不将模型、loss backward或AdamW改为float64，不放大KD系数，不缩batch制造更大效应，不增加优化步，不改变物品或探测池。那些都会改变干预，不能作为本精度复核的替代。

必须分开报告三件事：

|层次|本方案能回答的范围|
|---|---|
|float32更新本身的量化|记录焦点参数变化行、非零分量及两分支状态；它是既定训练器的实际干预，不用更高精度优化器“修复”|
|更新后效用的计算舍入|同一A/B状态比较原float32探测、先转float64再计算的探测、独立高精度参考；这是本次核心|
|有限训练边/负样本的统计不确定性|保留A/B/C、独立正边数和重复数；本方案不靠提升精度消除抽样噪声，不以3物品估计一般选择收益|

## 3. 建议实现范围（需下一步单独授权）

### 3.1 同状态的三条探测读数

- 原始读数：保留float32评分、logsigmoid与原保守筛查，便于追溯。
- float64读数：先从A/B取所需user/positive/negative行，**在乘法和求和前**转换到float64，再计算margin与稳定softplus。只转换少量探测行；不复制教师、不改变模型存储或优化器。
- 独立CPU参考：保存被探测的原float32行数值与其身份，用独立的高精度标量运算重算点积和loss差；例如Python Decimal 80/120位两档验证参考自身收敛。不能只是同一torch函数换设备后称独立参考。参考输入必须来自同一A/B，不再执行一遍优化来生成“参考模型”。

需要同时报告逐三元组值、角色均值、按既定角色概率加权的池贡献。`float32-float64`差只是两种读数差，只有对照独立参考才能估计评价误差。参考精度变化的一致性也是工程证据，不自动成为严格区间算术证明。

### 3.2 避免相近损失的直接相减

设 `mA=u·pA-u·nA`、`d=mB-mA`，BPR损失 `L(m)=log(1+exp(-m))`。恒等式为：

```text
L(mA)-L(mA+d) = -log1p(sigmoid(-mA) * expm1(-d))
```

由两分支非焦点行相等的硬检查，d也可直接由焦点参数差计算：

- 正角色：`d=dot(u64, itemB64-itemA64)`；
- 负角色：`d=-dot(u64, itemB64-itemA64)`。

这里先转64再相减，避免先在float32相减造成额外舍入；不能用两个float32 margin相减代替。恒等式不是一阶线性近似，也不需要梯度预测器。实现必须用正负角色合成数据核对符号、零干预、极小d和较大margin，并给大幅度d设置安全分支，避免expm1溢出或log1p接近定义域边界。不能未经测试就把该表达式当作通用安全实现。

普通float64 loss差、上述差分式、独立参考三者均保留，用来定位点积、非线性或减法误差。若参考不一致，停止解释效用，不以更有利的版本挑选结果。

### 3.3 保留可审计的最小中间量

建议新产物保存：计划JSON原字节身份；输入/输出状态与焦点行哈希；参与探测的原float32行（只涉及训练内ID）；每条的mA/mB/d、三种效用读数、实际误差、聚合权重和非零参数分量数。保留原P0目录，使用新命名空间，不覆盖旧报告。无需保存整套新checkpoint或逐样本全量梯度。

旧plan已有A/B/C与焦点IDs，不再次随机生成。精度复核只重用这些已曝光样本测数值一致性，不能把其C池再称作全新的最终选择审计集。若以后开展P1，须另行预注册未用于规则选择的审计安排。

## 4. 实现前要冻结的验证与停止规则

先完成仅合成输入的测试，不加载真实模型：

1. 原float32更新路径及优化器状态保持不变；合成同状态的所有读数均只读，零干预严格0。
2. 包含float32可表示的近邻参数、正/负角色、重复positive、margin正负及饱和区、极小d、loss消减和空角色。测试中用独立高精度参考，不以待测实现自身作为答案。
3. 各实现的绝对误差、符号及参考精度变化都逐条记录；未识别项不能被平均后假装消失。
4. 具体工程绝对/相对容限根据这些预先设计的合成测试和运算尺度确定，**在真实复核前写入新声明并冻结**。不根据真实收益符号调门槛，不把实用效应阈值与计算误差容限混为一谈。
5. 若用每条容限 `t_j`，角色均值误差界按 `sum(t_j)/n` 传播，加权池贡献按 `sum_role mass_role*t_role` 传播，并注明该界是已验证工程容限还是经过证明的误差界。仅对超出相应容限的读数标记数值可识别；统计可靠性另论。

未来真实复核必须另立一次新运行声明。建议仍限定原7对、单warm状态、原batch/物品/探测条目；各对只生成一次A/B，之后多种探测都读同一状态。暂用原600秒、CUDA allocator不超过原2GiB/25%较小者作为**计划上限**，经实现与合成检查确认后才成为启动约束。新跑不是旧失败重试，也不是悄悄继续旧P0；必要性在于旧产物缺少更新后状态与margin，无法离线补算。

因尚无实现和已验证容限，**本方案不提供可执行命令，不授权恢复/重放旧命令**。任何新GPU更新必须由用户另行批准并手动执行；原用户手动政策继续生效。

## 5. 如何决定是否继续

|复核可能结果|允许的结论/动作|
|---|---|
|合成测试或独立参考不一致|先修正测量实现；不执行真实诊断，不做科学解释|
|同状态高精度读数可信，部分真实信号超出计算容限|仅建立这些条目的数值可测性；仍需检查边覆盖与抽样不确定性，之后才能另议P1|
|数值可信但真实效用仍很小/大量为0|保留结果；不能由此证明所有物品无效，也不为求信号调大KD或扩样|
|GPU状态/精度参考不稳定，或预算不足|记录不可识别/部分结果并停止本预算，不自动重试|

现有源码与产物足以支持一个范围很小的精度检查具有必要性；**尚不足以判断它必然恢复有用信号**。建议下一步只授权实现上述只读探测组件、合成验证和一份新的用户手动声明；不同时授权真实运行。
