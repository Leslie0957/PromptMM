# 第二项路线收束评审

2026-09-30；依据4cafe23结果。仅比较两个候选；本次没有模型/数据矩阵加载、实验、实现或Test。结论不是第二算法已立项。

## 结论先行

**结束当前排序KD—邻居残差—低频分配的默认实验队列。两个新候选均未达到可以直接设计模块并开跑的证据标准。** 若继续探索，只优先核查“新物品入库时的表示生成与少交互适配”是否能形成可信协议；暂不推进压缩候选。不保证找到新算法，也不以换任务掩盖前述低结果。

当前已获得一批边界证据，第二项仍没有成立的独立贡献。第一项继续按原限定结论保留；THESIS_ROADMAP不改。这里是候选问题筛选，真正更换数据协议、教师或任务场景需形成明确方案再由用户决定，不自动执行。

## 为什么收束旧路线

| 证据 | 能支持 | 不能推出 |
|---|---|---|
| 排序监督三seed原配方停止 | 教师独有命中机会没有被该固定监督转为净收益 | 所有排序蒸馏无效，或必须再加门控 |
| 模态邻居有关联，但N低组输R | 关联不是所测残差机制有效性的充分条件 | 真实语义无用，或换更大网络必然有效 |

| Train标量U只较B多2/1/0命中 | 当前凸目标精确求解后实用增量仍很小 | 全部个性化校准不可能；也不支持继续盲调λ |

## 候选一：新物品入库时的内容表示生成与少交互适配

研究问题：在不为每次新物品入库重跑全图教师的预算约束下，如何利用物品图文生成可用于现有用户表打分的表示，并在少量交互到来后更新？

与第一项的区别：第一项是固定物品集合上的知识转移与成本权衡；此候选是未建立可靠ID向量的新物品接入能力。现行模型通过用户/物品ID索引取向量，代码没有给任意新内容生成学生向量的路径（main_mmlight.py的ID查表/BPR路径）。这构成能力缺口，不等于已证明实际部署损失或教师在新物品上有效。预分配随机ID行可以打分，也不等于具有内容驱动的归纳能力。

**不是把长尾改名为冷启动。** 既有低组大多数已有1–5次交互，只有5件零频物品；[稀疏统计](SPARSE_ITEM_ASSESSMENT_RESULTS.md)明确不是冷启动实验。暖启动优势也不能外推到教师没见过的新物品。

最近邻已有内容：

- [DropoutNet，NeurIPS2017](https://papers.nips.cc/paper_files/paper/2017/hash/dbd22ba3bd0df8f385bdac3e9f8be207-Abstract.html)：通过dropout训练为已有潜在模型提供冷启动能力。因此“内容生成向量/缺交互训练”不是新的贡献主张。
- [MWUF，SIGIR2021](https://arxiv.org/abs/2105.04790)：缩放/平移网络处理冷物品嵌入适配与噪声。因此“零交互→少交互的适配模块”也已有近邻。

以上是原始论文摘要/方法概述级核查，不是穷尽检索或完整复现审查。当前没有证据证明我们已避开这些方法。可研究的差异必须落到真实约束，例如在教师允许信息严格相同、固定入库/更新预算下，减少教师重算依赖而保持质量；但“离线映射+缓存”本身同样常见，不能预先认证工程创新。

最简单替代：冻结用户空间，训练一个线性或小MLP图文→向量映射；或内容近邻均值及标准少步BPR适配。任何复杂模块都须解释为何超出这些替代，不以Full为唯一弱对照。不预先加入图、置信门控或元学习。

关键缺口：尚无合法冷物品划分/时间信息核对；没有教师在冷物品上的有效性证据；没有首次入库/后续更新成本测量；没有可辨识的方法新增点。当前已有教师可能见过后续拟隐藏交互；从学生输入删掉边而复用该教师缓存会泄漏任务信息，不能称严格冷启动。

进入条件：先只读核对数据来源/时间字段/划分脚本和教师训练暴露范围。若做严格归纳场景，必须明确教师、图、统计量、映射训练均不能使用冷物品留出交互；冷物品内容是否在教师训练可见要分别标为transductive或inductive，而不能混用。新划分不得从已看Test指标选物品；旧Test本次仍禁止读取。无法避免教师交互泄漏或重建教师预算不可接受时，停止此候选，而不是降低标准后沿用“冷启动”名称。

资源风险：可能需要新的教师/数据资产，远高于刚才CPU校准；本次不做耗时承诺或建议立即训练。可复用的是工程与审计流程，不能预设复用旧教师张量就合格。

## 候选二：明确表存储预算下的教师知识压缩

研究问题：在小于64维FP32两张表的固定存储预算下，能否比普通降维/量化保留更多推荐信息，并减少真实部署开销？

支持动机：现有同维学生和缓存教师表大小相同，没有一致在线优势；要主张表存储降本，必须真的减少字节数。Sports现行两表约(35598+18357)×64×4=13,812,480 bytes（仅权重），不把工业百GB痛点强加给本机数据。

近邻：[Mixed Dimension Embeddings](https://arxiv.org/abs/1909.11810)已按查询频率分配向量维度；[Mixed-Precision Embeddings](https://arxiv.org/abs/2409.20305)已研究精度分配的准确率/内存权衡。按频次给不同维度/位数不是新的机制。

最简单替代：统一降低维度、FP16/INT8或标准低秩分解，配相同数据和预算；缓存教师和暖BPR都要纳入，不仅对比原图前向。存储比较需计投影、量化尺度、索引及解码开销；不能压缩存储后展开成64维FP32在线表，却仍宣称在线内存降低。

缺证据：没有容量/精度曲线或误差敏感性证据；没有独立算法差异。只跑若干维度是第一项扩展/成本消融，不自动成为第二项。也没有理由当前就假设尾部应分更多或更少容量。

决策：**暂缓。** 与第一项重合较高，且数据规模下真实内存需求未建立；不因论文缺第二项就开启压缩扫参。

## 最终排序与停止边界

| 判据 | 新物品接入 | 表预算压缩 |
|---|---|---|
| 当前可确认的问题 | 现行纯查表缺少内容生成新向量路径 | 同维不降表存储，事实明确 |
| 额外收益已证实？ | 否 | 否 |
| 独立方法差异已明确？ | 否 | 否 |
| 与第一项区分 | 新实体接入/更新任务，较清楚 | 很容易退化为第一项成本消融 |
| 主要阻碍 | 合法划分、教师泄漏、简单映射已有先例 | 真实预算需求、已有压缩方法强、范围重合 |
| 当前处置 | 仅优先做一次协议可行性核查 | 暂缓，不建实验队列 |

优先候选一是基于结构缺口和任务区分的研究判断，不是预测其更高Recall或更强创新。若协议核查不通过，两个候选均暂缓；停止新增运行，保留现有资产，先与导师确认第二项的贡献形式和剩余时间。外部学位要求会影响可接受路线，但不会改变现有证据。

**唯一下一步：只读核查“新物品接入”协议可行性**，限已有数据/教师元数据、预处理与划分代码；不读取Test、不生成新split、不载入模型或跑评价。交付可行/不可行及必须重建资产、预计成本类别和未决条件；不设计模块或训练队列。这是本次评审的优先建议，不是已授权后续运行。
