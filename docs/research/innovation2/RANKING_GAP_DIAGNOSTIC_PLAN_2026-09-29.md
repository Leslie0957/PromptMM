# 第二项候选：教师排序信息缺口诊断执行计划

版本1.0，2026-09-29。状态：计划完成，未实现、未运行。整体目标沿用[论文路线](../../../THESIS_ROADMAP.md)。用户将本计划交给另一AI明确要求执行后，可将下述准备、一次串行诊断cohort和收尾视为同一阶段；本文件本身不授权运行。全部完成后停止，交回独立审计，不自行进入训练。

## 1. 要回答的问题与已知边界

在现有Sports纯ID学生中，教师有利的候选排序差异是否仍存在于“教师初始化+BPR”之外，值得进一步检验排序监督？本阶段只测量机会，不证明缺少排序KD是性能瓶颈，也不认证算法创新。

当前Full仅对采样正物品进行图文方向监督，用户KD为零；没有直接教师用户级排序目标。但方向监督可能间接改变排序，不能写成学生完全得不到排序信息。

[三seed审计](../INITIALIZATION_KD_THREE_SEED_INDEPENDENT_AUDIT_2026-09-28.md)已表明：随机Full末轮约.082，教师初始化+BPR约.095；同一教师初始约.09418。净Recall差已经已知，本次不能把复算差值包装成新发现。新增信息是逐用户/逐留出正例的双向命中分解、重合与分布。所有学生同维，复制教师最终用户/物品表可复现对应内积排序，因此只超过随机Full不足以证明新方法价值。

## 2. 固定范围：一项诊断，七个评分状态

- 数据集仅Sports；不新训练、不更新参数或优化器、不读Test、不新增seed、不扫描best或中间epoch。
- 三个既有seed2022/2023/2024，各取初始化实验R1（随机Full）和T0（教师初始化+BPR）的final epoch300，共六个checkpoint。来源为exp/initialization_kd_interaction/下原manifest及三seedverification记录，不取正式Test主表或成本组的其他checkpoint。
- 第七个状态是三seed共同教师初始化所用的最终融合用户/物品表（不是图文分支缓存）。优先复用逐位绑定的既有初始化表；若只有冻结生成路径，先在准备中确定一次确定性导出及原epoch0指标核验方案。资产无法追溯则停止准备，不替换教师。
- 准备manifest精确列出实际路径、SHA256、形状、dtype、原source/config、数据映射和Train/Validation身份。复用可信共享锚，不重哈希无关大资产；实际使用的六个checkpoint和评分表需验证身份。
- 模型只读、eval/no_grad；不实例化可自动载入Test的通用数据加载器。读取Train只为排除已知交互及计算频次，Validation仅作评价标签。未观测候选不是已证实负偏好。

## 3. 评价协议与数值验收

使用原初始化实验的全物品候选、用户集合、训练已知物品过滤、Recall分母及K=20协议。禁止根据教师top列表或Validation标签缩候选。所有七状态使用相同用户顺序/候选规则；不保存全用户×全物品分数矩阵。

准备阶段核对原代码的打分精度、TF32与tie处理。保留原评价行为用于数值回归；若边界同分导致实现差异，记录数量与处理，不事后选择更有利的tie规则。候选排名用分块内积，输出每个状态的top20 ID、每用户留出正例命中ID及Recall；不必计算全量正例精确名次，避免扩大成本。

硬验收：六学生Recall@20与三seed审计epoch300对应值绝对误差≤1e-6；教师对应epoch0=.094184495190847733同样容差。若不匹配，保留结果并标记协议/数值验收失败，不能直接解释为科学差异或放宽容差。只读定位原因；重跑另获授权。所有有效分数有限（过滤掩码的负无穷除外）、ID合法、top20无重复且不含训练已知项、输入/输出数量一致、无参数更新、Test访问计数零。

## 4. 必须输出的指标

对用户u，V_u为该协议的Validation正例集合，H_T(u)、H_S(u)为各自top20命中的V_u子集。与原评估一致处理空V_u，不自行改变用户分母。

- G_u=|H_T(u)\H_S(u)|/|V_u|：教师独有命中。
- L_u=|H_S(u)\H_T(u)|/|V_u|：学生独有命中。
- G=mean_u G_u，L=mean_u L_u，N=G−L。必须校验N=Recall_T−Recall_S（容差1e-10，聚合使用float64）。N是已知净差的分解，不是独立机制证据。
- 同时报共同命中、双方均未命中、至少一个教师独有命中的用户占比、top20集合重合率。G不能当作可实现提升：它借助真实标签区分好坏，属于oracle机会描述。
- 六行主矩阵：seed×R1/T0，包含Recall_T/S、G/L/N、用户占比及重合率。教师只有一套，不把它当三个独立教师重复。
- 用户按Train交互数分低/中/高三组：排序键(交互数,user_id)，按人数三等分，分组在评分前固定；物品按Train频次同理分组。报告人数/正例数及各组G/L贡献，不将分组结果称为长尾改进。物品组贡献沿用全体用户和每用户|V_u|分母，三组贡献应相加等于总体。
- 可报告2000次用户簇配对bootstrap描述性95%区间，固定rng seed=20260929，同一次重采样用于所有状态；同一用户的全部正例一起重采样。不合并三个seed当三倍用户，不作显著性/泛化结论，不用区间修改下述门槛。

## 5. 事前决策规则（描述性资源筛查）

固定δ=0.001绝对Recall@20，即0.1个百分点，作为值得追加因果对照的最低机会量；不是统计标准、学位标准或预测的实际增益。它是本计划的资源分配选择，非由新诊断结果拟合。不得运行后下调门槛。

1. 任一硬验收失败：technical_fail/partial，不能作科学停止结论。
2. 三个T0的G都≥δ：opportunity_present。只说明简单初始化后仍有教师独有的留出命中，值得审议一次最简单排序监督因果对照；若N≤0，应明确这是互补机会、不是教师整体更优，盲目模仿可能损失L。无论G多大均不得直接启动训练。
3. 三个T0的G都<δ：screen_stop。当前协议下优先级不足，停止这条候选；即便R1有大缺口，也先接受初始化这一简单替代方案。不宣称所有排序蒸馏无效。
4. T0跨seed有的≥δ、有的<δ：inconclusive，保留全部结果，交审计；不加seed、不改δ或候选分布补过门。

R1结果仅定位随机训练的缺口，不单独触发继续。分组只描述集中性，不从最有利子组选择新主终点。这里不能识别可学习的教师可靠性、更不能证明一个选择模块有效；机会存在之后仍需独立训练对照及近邻文献核查，均不在本阶段。

B. 一次cohort：顺序完成七状态、聚合、资源与硬验收。单次启动，无自动重试/恢复，不训练。用户未委托执行时仅交付准备与精确命令。本计划不虚构尚不存在的脚本命令；执行AI必须在正式启动前以实际实现补全并提交命令。

资源上限：墙钟30分钟、CUDA allocator峰值2GiB、进程RSS4GiB、新增产物512MiB、开始前可用磁盘≥2GiB。用户批大小最多256、一次只放一个模型/评分块，bootstrap在CPU上分块聚合。资源检查要能触发停止，记录采样间隔和非OS硬隔离限制；若准备时发现无法遵守，停在准备报告，不自行加预算。记录总耗时、加载/评分/聚合分段耗时、峰值显存/RSS、输出大小；这些仅为诊断成本，不是新算法训练或部署成本。
